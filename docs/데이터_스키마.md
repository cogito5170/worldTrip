# Research schema (write ONE JSON file, UTF-8, valid JSON)

Top level: {"region": "<id>", "researched_on": "2026-10-01", "cities": [...], "edges": [...], "gaps": ["what you could not find"]}

## price object (EVERY number must be one of these)
{"min": number, "max": number, "currency": "JPY|KRW|EUR|GBP|USD|THB|VND|TWD|SGD|CZK",
 "unit": "per night" | "per person" | "per day" | "per ticket" | "per ride" | "per pass",
 "source": {"url": "https://...", "level": "full" | "snippet", "date": "YYYY-MM (when the source says the price applies, or publish date)", "query": "the search query you used"}}
- level "full" ONLY if you actually fetched and read the page (WebFetch). Search-result snippets are "snippet".
- free entry: min=max=0 with a source that says it is free.

## edge object (intra-region ground/air links between YOUR cities)
{"from": "tokyo", "to": "kyoto", "mode": "train|flight|bus|ferry|night_train", "hours": 2.3,
 "price": price (per person, one way), "frequency_ko": "e.g. 매시간 여러 편", "notes_ko": "..."}
Edges are undirected (do not add the reverse).

## HARD RULES
1. NEVER invent a number, a review, a restaurant, or a URL. If you cannot find it, leave the item out and add a line to "gaps".
2. Reviews must be paraphrases of real review/forum pages you saw (TripAdvisor, Reddit, Google reviews quoted in articles, blogs). No fabricated quotes, no invented reviewer names.
3. Prefer official sites (attraction ticket pages, rail operators). Prices should be current (2025-2026); put the date the source applies in source.date.
4. Ranges are fine and preferred (min/max). Use the local currency.
5. Each source.url must be a page you saw in search results or fetched.
